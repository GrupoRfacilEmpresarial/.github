# EXC-2026-012 - Cadena de 5 PR de tipos de plantilla custom en NewPdfGenV3: tamaño

| Campo | Valor |
|---|---|
| Fecha de registro | 2026-10-28 |
| Estado | Propuesta. Queda vigente cuando el Version Owner de NewPdfGenV3 la apruebe (merge de este registro). Registrada **después** de abrir el PR 1 de la cadena (#53) y **antes** de abrir los PR 2 a 5: ver el aviso de abajo. |
| Alcance | Cinco (5) pull requests de `GrupoRfacilEmpresarial/NewPdfGenV3` hacia `develop`, nombrados abajo. No alcanza a ningún otro PR de ese repositorio. |

> **AVISO AL QUE ACEPTA.** El PR #53 se abrió el 2026-10-28 a las 20:25 UTC y esta excepción se
> registra ese mismo día, dentro de las 24 h de la sección 17.3. La revisión de #53 señaló la
> desviación y este documento la formaliza para toda la cadena. Las cifras de los PR 1 y 2 se
> midieron el 2026-10-28 sobre sus ramas; las de los PR 3 a 5 son estimaciones con tope.

Pull requests cubiertos (secuenciales: cada uno sale de `develop` después de fusionar el anterior):

1. `feat/custom-tipos-01-modelo` (#53): núcleo del modelo (validación del tipo, esquema del modelo,
   armado del modelo desde JSON). Sin efecto en runtime.
2. `feat/custom-tipos-02-generate`: endpoint `POST api/CustomPdf/generate`.
3. `feat/custom-tipos-03-ciclo-tipo`: alta y borrado del tipo, exportar e importar.
4. `feat/custom-tipos-04-editor-esquema`: editor del esquema, guardia de cambios incompatibles y
   pistas del editor.
5. `feat/custom-tipos-05-preview`: JSON de muestra, vista previa y header/footer.

**1. Regla que se incumple.** Sección 0.2, regla 2, y sección 13.2: tamaño de PR <= 400 líneas;
sobre 1.000, **justificar o partir**. Cifras medidas (líneas agregadas / eliminadas):

| PR | Producción | Pruebas | Total |
|---|---|---|---|
| 1 (#53) | +651 / -0 | +1.144 / -0 | +1.795 |
| 2 | +554 / -13 | +2.280 / -0 | +2.847 |
| 3 a 5 (estimado, cada uno) | <= 1.300 | sin tope propio | <= 3.500 |

En los PR 1 y 2 el código de producto está por debajo de 1.000 líneas; lo que supera el umbral son
las pruebas (TDD estricto, una prueba por escenario de la especificación). Los PR 3 a 5 agregan
además frontend, que en este repositorio no lleva pruebas automatizadas.

**2. Motivo y por qué no había alternativa.** La alternativa existía y se consideró: el plan inicial
partía el trabajo en unos 21 PR de 400 líneas o menos. El autor eligió 5 PR verticales (backend y
frontend por capacidad) para reducir el costo de coordinación de una cadena secuencial de 21
pasos, cada uno con su revisión, CI y despliegue a dev. Esta excepción no afirma que no hubiera
alternativa: pide que se acepte no tomarla **para estos cinco PR**.

**3. Riesgo aceptado y quién lo acepta.** El riesgo es de **revisión de baja efectividad** sobre
PR grandes (sección 13.2). Está acotado porque el código de producto por PR queda cerca o debajo
de 1.000 líneas y el resto son pruebas que se revisan por nombre de escenario.

Controles compensatorios: TDD estricto con cada escenario de la especificación mapeado a una
prueba; las pruebas existentes de resolución CFDI corren sin modificarse en cada PR; revisión
independiente por PR (confiabilidad en el PR 1; riesgo, legibilidad, confiabilidad y resiliencia
en el PR 2) antes de pedir revisión humana; CI en verde; plan de reversión en cada descripción.

**Esta excepción NO cubre** la falta de ticket enlazado (sección 13.2), que la revisión de #53
señaló aparte.

Acepta: el **Version Owner de NewPdfGenV3**, al aprobar este registro.

**4. Plan y fecha para volver al estándar.** No aplica un retorno gradual: la excepción se agota con
el merge del PR 5 y queda cerrada ahí. Si algún PR de la cadena supera el tope de la tabla, se
parte o se registra una excepción nueva; no se estira esta. Después de la cadena, el trabajo
siguiente de NewPdfGenV3 entra en PR de 400 líneas o menos.

Punto de revisión: **2026-12-01**, en la retrospectiva trimestral (§14.3). Es la tercera excepción
por tamaño, después de `EXC-2026-010` y `EXC-2026-011`. Aquí el exceso viene de las pruebas, no del
código de producto: la retrospectiva debe mirar si el gate de tamaño debe medir las pruebas aparte
en lugar de acumular excepciones (sección 17.3).
