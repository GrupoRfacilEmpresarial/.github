# EXC-2026-004 — Regla global de CODEOWNERS comentada en `rfacil-ui`

| Campo | Valor |
|---|---|
| Fecha de registro | 2026-09-14 |
| Fecha de la desviación | 2026-09-08 |
| Estado | Vigente, con plan de retorno |
| Alcance | Un (1) repositorio: `rfacil-ui`, archivo `.github/CODEOWNERS` |

**1. Regla que se incumple.** Sección 13.1: propiedad global de code owner. La regla
`* @GrupoRfacilEmpresarial/ui-design-system` está comentada en el archivo `CODEOWNERS` del
repositorio. De los 41 repositorios de la organización, 39 tienen la regla global activa;
`rfacil-ui` es uno de los dos que no (el otro, `.github`, directamente no tiene archivo).

**2. Motivo y por qué no había alternativa.** La desviación se aplicó de forma deliberada el
2026-09-08 y **nunca se archivó como excepción**. Este registro la regulariza: no la crea, la
saca a la luz.

El motivo original no está documentado en ningún lado. No se infiere aquí. **El equipo
`ui-design-system` debe completar esta sección**; hasta entonces la excepción queda vigente con
su motivo incompleto, que es en sí mismo el hallazgo.

Se registra ahora porque el cambio `org-ruleset-gates` iba a agregarle a `rfacil-ui` una segunda
excepción (EXC-2026-003) mientras esta primera seguía sin existir en el registro. Apilar una
desviación documentada sobre una indocumentada es como se pudre un registro de excepciones: el
que cumple el trámite queda visible y el que no lo cumple queda invisible, hasta que el registro
describe una organización que no existe.

**3. Riesgo aceptado y quién lo acepta.** Un pull request en `rfacil-ui` puede aprobarse sin
revisión del equipo propietario. Con el gate de pull request activo sobre los 41 repositorios,
`rfacil-ui` exige pull request como todos, pero es de los pocos donde la aprobación no queda
anclada a un code owner nombrado.

Acepta: **`rodrigozalpich`**, en su rol de **Release Manager** (equipo
`GrupoRfacilEmpresarial/release-managers`, id 19478536).

> **Autoaprobación declarada.** Vale la misma nota que en EXC-2026-003: quien impulsa el cambio
> también acepta la excepción. Se planteó la objeción antes de decidir y se aceptó a conciencia.
> Registrado para que la revisión trimestral de la sección 14.3 lo mire, no para que lo
> descubra.

> **Sucesión de aceptante.** El aceptante se nombra como **persona más rol**. Cuando cambie
> quien ocupa el rol de Release Manager, el aceptante de este registro es quien lo suceda en el
> equipo `release-managers`.

**4. Plan y fecha para volver al estándar.** Descomentar
`* @GrupoRfacilEmpresarial/ui-design-system` en el `CODEOWNERS` de `rfacil-ui`. Es un cambio de
una línea; lo que falta no es el trabajo sino la decisión del equipo propietario sobre si la
regla global es la correcta para ese repositorio o si necesita una forma distinta.

Punto de revisión: **2026-12-01**, el mismo checkpoint comprometido para el apriete del gate de
pull request. Para esa fecha la sección 2 de este registro debe estar completa: una excepción
sin motivo documentado no se renueva.
